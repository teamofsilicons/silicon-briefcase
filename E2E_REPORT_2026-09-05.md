# Briefcase / IAM end-to-end test report

## Outcome

The exercised Briefcase backend, Rust client, and CLI workflows pass after the fixes below. This is **not an unconditional all-green release sign-off**: fresh-member onboarding and importing the same application into multiple IAM environments still have integration blockers. OBO also intentionally lacks delegated tag/admin authority; that does not yet meet the broadest reading of “any location for that user.”

The run used the locally rebuilt IAM at `b57848c` and installed IAM CLI **1.1.1**, Briefcase's current working tree, and Briefcase client/CLI **0.1.1**. IAM source was not modified. Existing worktree changes, including both repositories' user-edited `UNDERSTANDING.md`, were preserved. No commit was made.

## Fixes made during this run

1. **Permanent/content URL corruption:** a legal backslash in an entry name was normalized into a path separator. `src/api/mapping.rs` now encodes it as `%5C`. A regression covers backslashes, Unicode, percent signs, spaces, and URL delimiters; the running CLI resolved a backslash-containing path correctly.
2. **IAM permission projection corruption:** OBO's deliberately restricted member authority could overwrite the represented owner's signed role/tags. Request bootstrap now preserves existing OBO projections and all positively versioned IAM snapshots. This also prevents an older in-flight bearer request from undoing a newer signed demotion. The PostgreSQL regression exercises both cases, including tag preservation. A real OBO upload preserved the owner's role after the fix.
3. **Incorrect OBO error classification:** IAM rejects altered request bytes with HTTP 403, but Briefcase reported a dependency outage (503). Proof refusals now produce authentication rejection; actual service credential failures and upstream outages remain dependency failures. Added a seven-status regression and verified tampered bytes against the running IAM.
4. **Durable live client coverage:** completed the opt-in disposable file-workflow test in `../briefcase-client-rust/crates/briefcase-client/tests/live.rs`, including idempotency, ranges, versions, permissions, movement, bin/restore, history, and cleanup.

## Remaining blockers and limits

### IAM multi-environment application import

Importing `briefcase-e2e>briefcase` into another environment in the already-used IAM testing database returned **409 `testing_import_organization_not_managed`**. The fresh test Carbon had no organization membership, while another environment already contained that public organization handle.

`iam_private.organization_handle_is_available(text)` is a security-definer function whose query checks the handle without an environment predicate (`silicon-iam/migrations/0006_audit_outbox_and_rls.sql`). The observed cross-environment collision is consistent with that lookup bypassing environment isolation.

To continue testing without modifying IAM or erasing old environments, this run created `silicon_iam_testing_bc_20260905`, applied the official migrations/runtime grants, and pointed the local IAM runtime at it. Import succeeded there. This workaround does **not** prove multi-environment import is fixed.

### Initial membership projection / post-clean onboarding

A fresh valid app login can succeed while Briefcase file access returns **403**, because IAM has not delivered the principal/membership/authorization-epoch projection needed by Briefcase. An ordinary login event does not contain that snapshot. Application access tokens also received **403** from IAM's member/directory endpoints; `direct_iam_binding` currently excludes application sessions.

The run used real IAM directory mutations and received real signed webhooks, then obtained fresh SLTs after epoch changes. No membership rows or signatures were forged. Initial login and post-clean onboarding still need a supported initial-snapshot/synchronization contract; requiring an unrelated directory edit is not a production solution.

### OBO's “any location” requirement

IAM's verified proof establishes the represented actor but does not expose the role/tag authorization binding used for normal bearer requests. Briefcase conservatively uses baseline member authority for OBO. Own/private application folders and public destinations work; tag-only or admin-only destinations are not fully supported. Broadening this safely requires current delegated authority from IAM, not simply trusting an unbound cached role.

### Test scope, not promises

- A burst of approximately 100+ introspections hit IAM's rate limit. Briefcase returned 503 and recovered after the limit window; functional pagination ran at a paced rate. No throughput/SLA claim is made.
- Object storage was local MinIO. Real AWS STS/BYO-bucket/KMS integration and outbound external event delivery were not configured or certified. The worker truthfully reports unconfigured external dispatch.
- Retention expiry/quota/lifecycle races were exercised through database tests; this run did not wait 45 days or perform a multi-gigabyte quota exhaustion through the public network API.
- The client tested here is the Rust package, not a browser UI. No browser-front-end sign-off is implied.
